# 行政書士 学習分野 構築タスク（/loop 用マスター指示書）

このドキュメントは `/loop` から自律実行される前提の**作業指示書**です。
`shikaku/gyosei/` 配下に、行政書士資格の学習コンテンツ（試験概要・用語集・過去問演習）を、
既存の宅建分野（`shikaku/takken/`）と同じ構造・作法で段階的に構築します。

> **前提**: 各イテレーションは「PROGRESS.md を読む → 未完タスクを1つ選ぶ → 実行 → 検証 → PROGRESS.md を更新」の
> 単位で完結させること。1回で全部を作ろうとしないこと。中断・再開しても状態が壊れないことが最優先。

---

## 0. まず最初にやること（毎イテレーション共通の手順）

1. `shikaku/gyosei/docs/PROGRESS.md` を読む。これが唯一の正となる進捗表。
2. 進行中（`[~]`）タスクがあればそれを継続。なければ未着手（`[ ]`）の**最上位タスクを1つだけ**選ぶ。
3. タスクを実行する（原則、1イテレーション＝1チャンク。目安は下記「作業粒度」）。
4. 生成物を**自己検証**（後述のチェック項目）。
5. PROGRESS.md の該当行を `[x]` に更新し、件数・日付を記録。必要なら次タスクを `[~]` にする。
6. 全タスクが `[x]` になったら「完了条件」を満たすか最終確認し、満たしていればループを終了する。

**作業粒度の目安（1イテレーションで扱う量）**
- 用語集: 1トピック分 = **30〜50語**まで
- 過去問: 1科目の1トピック分 = **8〜12問**まで
- 概要・まとめページ: 1ファイル単位

大きすぎるチャンクは正確性が落ちるため、必ず分割すること。

## 2. 正確性ルール（最重要・厳守）

グローバル方針「**推測で断定しない**」に従う。

- **試験制度・配点・日程・合格基準は必ず一次情報で裏を取る。**
  一次情報 = 一般財団法人 行政書士試験研究センター（`https://gyosei-shiken.or.jp/`）。
  補助として大手予備校（LEC / TAC / 伊藤塾 等）を参照可。数値が食い違う場合は一次情報を優先。
- **行政書士試験は令和6年度（2024年度）に出題科目が改正**されている（旧「一般知識等」→「基礎知識」）。
  古い情報を写さないこと。最初の概要作成イテレーションで現行制度を確認・明記する。
- 用語の定義・過去問の解説は、条文・判例・制度に照らして正しいことを確認する。
  自信が持てない項目は作らず、PROGRESS.md に「要確認」として残す。
- 断定できない箇所には出典を併記するか、「※最新情報は試験研究センターで要確認」と明示する。
- 本コンテンツは個人学習目的。各ページのフッターにその旨のディスクレーマを入れる（宅建に倣う）。

## 3. データスキーマ（宅建と完全互換にすること）

### 3-1. 科目別 過去問 JSON（`data/<subject>.json`）

宅建 `takken/data/gyoho.json` と同一構造：

```json
{
  "subject": "行政法",
  "updated": "2026-08-04",
  "questions": [
    {
      "id": "gyoseiho-001",
      "subject": "行政法",
      "topic": "行政行為の効力",
      "question": "行政行為に関する次の記述のうち、正しいものはどれか。",
      "choices": [
        "1. ……",
        "2. ……",
        "3. ……",
        "4. ……",
        "5. ……"
      ],
      "answer": 3,
      "explanation": "……（なぜ正解か・他の選択肢がなぜ誤りかを条文/判例に基づき説明）",
      "law": "行政手続法第○条 / ○○判決",
      "difficulty": "基本"
    }
  ]
}
```

- **行政書士の択一は5肢択一**。`choices` は原則5個、`answer` は 1〜5。
  （宅建は4肢だが、`practice.html`/`quiz.html` の描画は選択肢数に依存しないため5肢で問題ない。）
- `id` は `<subject-slug>-NNN`（3桁ゼロ埋め、科目内で連番）。
- `difficulty` は `基本` / `標準` / `応用` のいずれか。
- `topic` は科目内の論点名。用語集の分類とできるだけ揃える。
- 多肢選択式・記述式は v1 では対象外（`択一式`のみ）。将来対応する場合も既存UIを壊さない形にする。

**subject 文字列と slug の対応（厳守。表記ゆれ禁止）**

| subject（表示名） | slug / ファイル名 | 備考 |
|---|---|---|
| 基礎法学 | `kisohogaku` | |
| 憲法 | `kenpo` | |
| 行政法 | `gyoseiho` | 最重要・最多出題 |
| 民法 | `minpo` | |
| 商法・会社法 | `shoho` | |
| 基礎知識 | `chishiki` | 旧・一般知識等。政治経済社会/情報通信/個人情報保護/文章理解 |

### 3-2. 統合ファイル `data/questions.js`（自動生成物）

宅建 `takken/data/questions.js` と同形式。全科目JSONの `questions` を連結し、
グローバル定数として出力する。**手編集禁止**（JSON側を直し、この工程で再生成する）。

```js
// 行政書士 過去問演習データ（全科目統合）
// data/*.json から自動生成（編集はJSON側で行うこと）
const QUESTIONS = [
  { "id": "gyoseiho-001", ... },
  ...
];
```

生成手順（毎回JSONを更新したら再生成する）:
```bash
cd shikaku/gyosei/data
python3 - <<'PY'
import json, glob
files = ["kisohogaku","kenpo","gyoseiho","minpo","shoho","chishiki"]
out = []
for f in files:
    try:
        out += json.load(open(f+".json", encoding="utf-8")).get("questions", [])
    except FileNotFoundError:
        pass
with open("questions.js","w",encoding="utf-8") as w:
    w.write("// 行政書士 過去問演習データ（全科目統合）\n")
    w.write("// data/*.json から自動生成（編集はJSON側で行うこと）\n")
    w.write("const QUESTIONS = ")
    json.dump(out, w, ensure_ascii=False, indent=2)
    w.write(";\n")
print("questions.js:", len(out), "問")
PY
```

### 3-3. 用語集 `data/flashcards.json`

宅建 `takken/data/flashcards.json` と同一構造：

```json
{
  "updated": "2026-08-04",
  "cards": [
    { "id": 1, "subject": "行政法", "term": "行政行為", "definition": "行政庁が法に基づき、公権力の行使として、国民の権利義務を一方的に決定する行為。処分ともいう。" }
  ]
}
```

- `id` は全カード通し番号（1から連番、重複禁止）。
- `subject` は §3-1 の表示名（`基礎法学`/`憲法`/`行政法`/`民法`/`商法・会社法`/`基礎知識`）。
- `definition` は1〜2文で簡潔に。試験で問われるポイントを含める。
- 同義語・重複語を作らない。追加前に既存 `term` と突き合わせて重複チェックする。

## 4. 用語集（約1000語）の分割方針

科目ごとに目標語数を割り当て、トピック単位で少しずつ埋める（1イテレーション30〜50語）。
配分は出題比重に概ね比例させる（合計 **約1000語**）。目安：

| 科目 | 目標語数 | 主な論点（トピック例） |
|---|---|---|
| 行政法 | 約300 | 行政法総論／行政手続法／行政不服審査法／行政事件訴訟法／国家賠償法／地方自治法 |
| 民法 | 約250 | 総則／物権／担保物権／債権総論／債権各論／親族・相続 |
| 憲法 | 約120 | 人権総論／各種人権／統治機構／憲法訴訟 |
| 商法・会社法 | 約100 | 商法総則・商行為／会社の設立／機関／株式／持分会社 |
| 基礎法学 | 約40 | 法の分類／法源／法解釈／裁判制度 |
| 基礎知識 | 約190 | 政治／経済／社会／情報通信・IT用語／個人情報保護法／行政書士法等関連法令／文章理解の技法 |
| **合計** | **約1000** | |

> 目標語数はあくまで目安。品質を優先し、無理に埋めない。到達できない科目は PROGRESS.md に理由を残す。

## 5. 過去問の分割方針

行政書士試験本試験は全60問だが、**学習用の問題バンク**として論点網羅を目的に作る。
目標 **約200問**を出題比重に応じて配分（1イテレーション8〜12問）。目安：

| 科目 | 目標問数 |
|---|---|
| 行政法 | 約70 |
| 民法 | 約45 |
| 憲法 | 約30 |
| 商法・会社法 | 約20 |
| 基礎知識 | 約25 |
| 基礎法学 | 約10 |
| **合計** | **約200** |

各問は §3-1 スキーマ厳守。作問後は必ず「正解の根拠」と「誤答肢の誤りの理由」を解説に書く。

## 6. HTMLページの作り方（宅建からの流用）

**原則、宅建の対応ファイルをコピーして行政書士向けに書き換える**（ゼロから書かない）。

- 共通スタイルは `shikaku/css/style.css` を流用（`<link rel="stylesheet" href="../css/style.css" />`）。
- 各ページ冒頭の Firebase 認証ガード（`onAuthStateChanged`）は宅建の各HTMLからそのまま流用。
  未ログイン時のリダイレクト先は `/shikaku/login.html`。
- パンくず・ヘッダー・フッターの「宅地建物取引士（宅建）」表記を「行政書士」に置換。
- データ参照先を gyosei 用に変更：
  - `practice.html`: fetch 対象を `data/kisohogaku.json … chishiki.json` の6ファイルに変更。
  - `flashcard.html`: `fetch('data/flashcards.json')` のまま（構造同一）。
  - `quiz.html`（作る場合）: `<script src="data/questions.js"></script>` のまま。
- 科目別まとめページ（`kenpo.html` 等）は宅建の科目ページ（`gyoho.html` 等）を雛形に、内容を差し替え。

**科目カラーコード（案。宅建の contents/README に倣い統一）**

| 科目 | カラー |
|---|---|
| 憲法 | `#4A90D9`（青） |
| 行政法 | `#E8A020`（橙） |
| 民法 | `#5BAD6F`（緑） |
| 商法・会社法 | `#C0564B`（赤） |
| 基礎法学 | `#7F8C8D`（灰） |
| 基礎知識 | `#9B59B6`（紫） |

**分野入口の追加**: `shikaku/index.html` の `.subject-grid` 内にある「WIP（`subject-card wip`）」カードのいずれか、
または新規カードを、行政書士の有効カード（`<a class="subject-card" href="gyosei/index.html">`）に置き換える。
試験日・問題数・合格率は §2 に従い一次情報で確認した値を入れる（未確認なら暫定値＋要確認メモ）。

## 7. 自己検証チェック（各イテレーション終了時）

- [ ] 生成した JSON が `python3 -c "import json,sys;json.load(open(sys.argv[1]))"` でパースできる。
- [ ] `answer` が `choices` の範囲内（1〜選択肢数）を指している。
- [ ] `id` の重複がない（科目内連番・flashcards は全体連番）。
- [ ] `subject` 表示名が §3-1 の表記と完全一致している。
- [ ] JSONを更新したら `questions.js` を再生成した（§3-2）。
- [ ] 概要・制度の数値は一次情報と整合（改正後の現行制度か）。
- [ ] HTMLを作った場合、ブラウザ相当で開けるか（相対パス・fetch先・認証ガードを目視確認）。
- [ ] PROGRESS.md を更新した。

---

## 8. 完了条件（ループ終了の判定）

以下がすべて満たされたらループを終了する：

1. `docs/overview.md` と `docs/overview.html` が現行制度で完成している。
2. `data/flashcards.json` が **約1000語**（各科目が §4 の目標に概ね到達、合計900語以上を許容ライン）。
3. `data/*.json`（6科目）合計 **約200問**（合計180問以上を許容ライン）。
4. `data/questions.js` が最新のJSONから再生成済み。
5. `index.html` / `practice.html` / `flashcard.html` / 科目別まとめページが動作する。
6. `shikaku/index.html` から行政書士分野に遷移できる。
7. 未解決の「要確認」項目が PROGRESS.md に残っていない（または残件が明示・許容済み）。

---

## 9. やらないこと / 注意

- 一次情報で確認できない数値を断定して書かない。
- 大量生成を1イテレーションに詰め込まない（正確性劣化・中断時の破損を招く）。
- `questions.js` を手編集しない（JSON→再生成のフローを守る）。
- 既存の宅建（`takken/`）や他分野のファイルを壊さない。変更は原則 `gyosei/` 配下と `shikaku/index.html` のみ。
- コミットはユーザーが明示的に指示した場合のみ行う。
